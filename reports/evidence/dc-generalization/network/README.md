# Generic convex monotone network evidence

The hand-written production leaf is `formalization/HiddenMonotonicity/ConvexMonotoneNetwork.lean`.

Target build (from `formalization`):

```sh
lake build +HiddenMonotonicity.ConvexMonotoneNetwork
lake env lean ../reports/evidence/dc-generalization/network/Exact.lean
lake env lean ../reports/evidence/dc-generalization/network/Boundary.lean
lake env lean ../reports/evidence/dc-generalization/network/Independent.lean
```

`expected-types.json` contains independently authored full-forall statements, not inferred or copied elaborated target types. `Exact.lean` is generated by the unchanged `formalization/scripts/verify.py:exact_driver` from that JSON. It checks exact types, module provenance and standard allowed axioms, then audits all 257 imported project theorem declarations. `environment.json` is the audit output.

`Independent.lean` was authored and compiled by a separate reviewer and supplies a max/identity ReLU instance of the complete theorem. `Boundary.lean` checks an identity activation, zero-width input, signed biases and genuinely negative stream values.

This is targeted development evidence. Public imports, manifest integration and the final clean committed verification remain separate.
