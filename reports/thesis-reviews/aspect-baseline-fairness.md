# Review of attribution baseline fairness

This review assesses the thesis's baseline comparisons, attribution-map conventions, and evaluation specification against the [master's thesis assessment framework](assessment-criteria.md). It examines the current TeX sources and the two pinned implementation repositories. The thesis combines a CVPR 2026 Highlight paper with an arXiv preprint; that is substantial research achievement, but publication status does not resolve the comparability questions below. This is a source and artifact inspection, not a rerun of the experiments or implementation tests.

My assessment is that the revised game campaign shows unusually serious attention to baseline fairness for a master's thesis. Nevertheless, the current presentation does not yet make an unqualified 1.0 case in this aspect: one comparative claim conflicts with the fuller results, and several important protocol distinctions require reconciliation. Most repairs are bounded documentation and reporting work, not a demand for another research project.

## What deserves credit

The game campaign does considerably more than compare a heavily tuned new method with unnamed defaults. It declares baseline grids, selects localization and faithfulness configurations independently on validation data, retains a theoretically defined anchor, and reports held-out results with paired uncertainty analysis. The selection code excludes failed maps and incomplete validation coverage before ranking. The source does not justify an allegation of test leakage. See [the protocol](../../tex/chapters/10_appendix.tex), `ptnb:app:grids` and `ptnb:app:selection`, and [selection code](../../code/playing_backward/reproduce/select_configs.py), lines 133–153 and 188–219.

The released code also contains comparisons with reference implementations for gradients, SmoothGrad, Integrated Gradients, DeepLIFT, and CAM methods; it explicitly tests the distinction between a black image and zero in normalized coordinates. These tests are meaningful safeguards, although this review did not execute them. Robustness perturbations are seeded by image, so methods see the same noisy inputs. The thesis additionally investigates Pointing Game granularity and reports where competing methods lead. Those choices deserve genuine weight in the assessment. See [baseline tests](../../code/playing_backward/tests/test_baseline_references.py), lines 1–9 and 88–165; [metric bridge](../../code/playing_backward/bwgame/evaluation/quantus_bridge.py), lines 280–317; and Appendix `ptnb:app:pg-granularity`.

## The ResNet-18 summary excludes a stronger localization baseline

**Must correct.** The experiments chapter says the split methods “edge the top localization scores,” comparing Attribution Localization 0.673 with LayerCAM's 0.664. However, the [full ResNet-18 table](../../tex/tables/appendix/xai_eval_res_full.tex), lines 67–68, reports Guided Grad-CAM at 0.742 and 0.717. Both exceed 0.673, and both rows are omitted from the [main table](../../tex/tables/eval_res_main.tex). The same paragraph calls LayerCAM at Selectivity 3.690 the strongest baseline, although Guided Backprop at 3.517 and LRP at 3.550 already appear in that main table; lower is better.

This is a verified reporting inconsistency, not evidence of intentional cherry-picking. The current main-table selection rule does not explain why the stronger localization comparator disappears. An excellent thesis must let a reader identify the strongest relevant competitor without discovering it independently in an appendix. Include the omitted comparator, or explain an independently justified eligibility restriction and narrow the claim accordingly. Correct the Selectivity comparator. **Done means:** every “best,” “strongest,” or “top” statement names its comparison set and agrees with all eligible rows; no new experiment is necessary.

## The Pixel Flipping definition must match the implemented feature space

**Must correct.** In Appendix `ptnb:app:metrics`, the spatial map dimension is defined as (d=HW), but the Pixel Flipping paragraph uses (T=\lceil d/1568\rceil) and subsequently states (T=96), with five and twenty curve points for PF5 and PF20. For a (224\times224) spatial map, that formula gives 32 steps. The implemented count is based on (CHW): the attribution is broadcast across color channels and scalar channel features are perturbed. The project explicitly computes the input-feature count at [quantus_bridge.py](../../code/playing_backward/bwgame/evaluation/quantus_bridge.py), lines 485–486, and its AUC helper uses ceiling cutoffs at lines 83–98.

Separate the spatial dimension from the input-feature dimension, define the broadcast attribution ranking, and state that the curve contains post-perturbation logits. Preserve the reported numbers unless a separate execution audit finds an implementation problem. **Done means:** the written equations reproduce 96, 5, and 20 from the stated input dimensions and settings. This is a specification defect; it does not establish that within-campaign method rankings are invalid.

## The two campaigns explain different output targets

**Needed for a persuasive 1.0 case.** The thesis helpfully distinguishes score-drop versus remaining-logit AUC, perturbation budgets, sample counts, and ResNet variants in [Chapter 8](../../tex/chapters/08_experiments.tex), lines 3–9. It should also distinguish the target-class policies found in the released code. The split pipeline explains the model's predicted argmax class: [map_generation.py](../../code/hidden_monotonicity/xai/evaluation/map_generation.py), lines 452–461 and 612–622. The game pipeline passes dataset labels to attribution methods: [evaluator.py](../../code/playing_backward/bwgame/evaluation/evaluator.py), lines 656–674 and 713–728. Its ImageNet-S pool explicitly aligns the dataset label with the segmented object: [imagenet_s.py](../../code/playing_backward/data/imagenet_s.py), lines 63–75.

These are different scientific questions on misclassified images. Localizing a predicted class against a ground-truth object mask is not equivalent to explaining the ground-truth class logit. This is not evidence that different methods within either campaign received different targets. Reconcile the archived run configurations with the released pipelines, state the target policy for each campaign, and report how misclassifications are treated. **Done means:** a reader can identify the explained output and mask class for every evaluation sample; any aggregate cross-campaign interpretation respects that difference. A new common-target benchmark is optional if comparisons remain within campaigns.

## Shared selection rules do not mean equal search opportunity

The declared ViT grid contains 672 RG configurations, 54 DAVE configurations, 11 AttnLRP configurations, four Integrated Gradients configurations, and three SmoothGrad configurations; LIME and KernelSHAP have fixed rows. These counts are transparent in Appendix `ptnb:tab:main-search-grid` and the [validation-selection summary](../../code/playing_backward/results_summary/selection/vit_b16/selection_summary.md), lines 18–30. A larger family reasonably needs a larger search, and validation-based selection followed by held-out testing remains legitimate. Equalizing every grid is not a prerequisite for an excellent master's thesis.

The limitation is interpretive: the observed advantage belongs to the selected method-and-search procedure. It does not isolate how much improvement comes from the game construction rather than its additional adjustable choices. The main comparison should say “under the declared validation grids,” show the anchor alongside selected results, and acknowledge the search asymmetry where superiority is claimed. A matched-budget selection analysis using existing validation outputs would strengthen the argument, but is optional if the claim is scoped appropriately.

The same issue applies to layers. The split campaign optimizes layers and demonstrates substantial layer dependence, whereas the game campaign fixes CAM baselines to the last convolutional block (Appendix lines 262–263). These are defensible reference baselines, but they are not demonstrated best-layer CAM baselines. Label that scope; do not imply exhaustive optimization.

## Map conventions need a compact audit trail

**Needed for a persuasive 1.0 case.** A common Quantus configuration does not make the maps entering it semantically identical. The implementation supports signed channel sums, sums of absolute values, and maximum absolute values; these can rank pixels differently even before metric normalization. See [captum_methods.py](../../code/playing_backward/bwgame/xai/methods/captum_methods.py), lines 33–51. The split campaign also selects absolute-value handling, while the game metrics generally score absolute maps. Consequently, benchmark success measures the chosen rendered map, not preservation of signed explanatory evidence by itself.

Add one concise per-method protocol table recording target policy, channel reduction, sign handling, spatial interpolation, reference input, selected layer, implementation version, and configuration identifier. Distinguish reference-prescribed conventions from tuned ones. Include the actual mean-baseline and feature-count definitions for perturbation metrics. **Done means:** each published row can be traced to its map-to-metric pipeline without reconstructing defaults across multiple modules. A supplementary sensitivity comparison is warranted only where a central conclusion depends on a disputed convention.

The fair conclusion is therefore neither that the benchmarks are careless nor that they already establish universal method superiority. The game campaign contains strong comparative safeguards; the remaining work is to make the strongest competitors, exact estimands, and limits of the tuning protocol equally visible in the thesis's headline account.
